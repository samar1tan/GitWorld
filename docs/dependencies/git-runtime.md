# Bundled Git runtime

GitWorld's data-revision adapter invokes a separately built Git executable with a controlled argument list and environment. Git manages the application's own local repository. It does not provide arbitrary shell access, import external repository configuration, or turn modern data edits into ancient historical events.

`node scripts/build-bundled-git.mjs` builds Git 2.56.0 from its pinned official source archive on macOS. It verifies SHA-256 before extracting or building. The recipe uses a generic runtime prefix, disables optional network/language-runtime dependencies and checks the result for private build paths and external dynamic libraries. It includes only the Git executable and its builtin-command entry point. Build outputs and logs remain in the ignored `.local/bundled-git` directory. `--verify-only` checks the exact cached artifact, source, recipe and runtime manifest; it does not silently accept a system Git installation.

This is a local Git runtime, not a full replacement for a system Git distribution. Normal installed operation does not require Git, Xcode, Node, Perl or Python to be installed separately. The build machine needs the declared macOS compiler and system tools. Other target platforms need their own build and execution evidence.

Git is separately licensed under the terms in its exact `COPYING` file, primarily GPL version 2; the GitWorld Apache-2.0 license does not relicense Git. The build preserves Git's license, sha1dc's MIT license, reftable's BSD license, and the LGPL 2.1 text used by xdiff and applicable GNU compatibility code. The LGPL text is obtained from the SPDX license-list-data project with a pinned content hash. Selected upstream source-file notice blocks are retained separately, including notices for source files outside this particular build. The complete unmodified upstream source archive retains all source-level notices; the manifest's actual compiled-object list identifies this build's selection. Distributions containing this runtime must also contain its `corresponding-source/` directory with the exact source archive, license text, configuration and build recipe, or provide another independently reviewed compliant source-delivery arrangement. A project link alone is not the selected source-delivery method.

The runtime manifest binds source hash, recipe hash, configuration, architecture, binary hashes and system-library dependencies. It is evidence about those exact build bytes, not a claim of bit-for-bit reproducibility across machines or a completed legal review. Release review must inspect the actual installer and corresponding-source assets together.

The repository's operational state includes `repository/` (working files, index, objects and refs), `editorial-operations.sqlite` (durable commit/retry receipts), and `editorial-write-lock.sqlite` (cross-process write coordination). Backup/restore must account for these files and the rest of the application's database/source archive; copying only committed Git objects would lose staged and unfinished work. SQLite coordination does not make a Git ref update and a SQLite write one atomic transaction. Recovery reuses the recorded commit OID and never rewinds a newer HEAD.

Staging imports canonical JSON blobs through the bundled Git `fast-import` protocol in batches of at most 32 MiB, including protocol bytes. Exact UTF-8 byte counts separate content from commands, and returned object IDs must match the expected Git blob hashes. The host emits only `blob`, `mark`, `data`, `get-mark` and `done`; no commit, branch, tag, reset, path or user-supplied directive enters this stream. This writes raw blob content without clean filters. `fastimport.unpackLimit=0` keeps the result packed rather than expanding small imports into separately synced loose objects; `core.fsync=all` and `core.fsyncMethod=fsync` remain enabled for Git's pack, metadata and index durability. Every import must finish successfully before a single atomic index replacement freezes the selection. A failed blob import can leave unreferenced object data, while the previous index, HEAD and working content remain available.
